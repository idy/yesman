# One-run model score package acceptance

This QA branch runs one macOS ARM64 job for PR #107. It is separate from the feature branch and must not be merged or used for a release. Its only trigger is a push to `qa/model-score-package-acceptance`; the job also refuses a rerun attempt. No PR, manual dispatch, main push, tag or secret is required.

Product source is fixed at `dfc9ad753ab97fae0b78104bd72d0392282a4ab5`, tree `4f8b8f55684e44a997294481768b06b2b64a379f`. The five files in `kit/` are byte-identical selections from the prepared acceptance ZIP SHA-256 `8d9b2b27e5e848800d45be7c19cd13c4e74611931c91142b37d07775a1f4981a`. `inputs.json` records their hashes and the complete QA file set. The original kit's workstation documentation, local validation helpers, ZIP, binaries and logs are intentionally not committed.

The workflow checks out its exact QA SHA and the exact product SHA separately, without persistent credentials. `hosted.py` verifies both trees and the QA parent/file set, then downloads pinned public Go modules in a clean environment. The original `prepare.py` makes two private production builds, with distinct newer synthetic score defaults and the updater disabled only in exported configuration. Product Go/web files, existing AA snapshots and release metadata remain unchanged. Both private packages retain the inherited version 0.1.45; no new version is allocated.

The original `run-native.py` requires a genuine GitHub-hosted macOS ARM64 GUI session and a fresh whole user profile. It runs the actual production MyGo bridge and Models renderer through the existing web-directory observer mechanism. A and B use the same private installation path, settings and patch bytes. The native executable/window and image hashes, effective values/provenance, State.home, profile hashes and normal shutdown are recorded. Inherited speed must change 120 to 210 tok/s; explicit CSV zeros and the patch-only score remain. No agent/provider, updater transaction, installer, permission action or production profile is used.

Only the allowlisted UTF-8 records in `hosted.py:RECORDS`, plus `validation.json` and a SHA-256 manifest, are uploaded. Each record is limited to 4 MiB and the existing records total to 16 MiB. They contain public source/tool identity, synthetic settings/score DTOs, disposable runner paths, package inspection, catalog methods and clean-environment build/app diagnostics. No package, executable, archive, profile directory, auth file, cache or arbitrary filesystem glob is uploaded. Partial evidence is retained if a step fails. Acceptance requires both native stages in `proof.json`, `passed: true`, validated pages and successful normal exits; setup success or browser-only results cannot substitute.

Keep the QA ref and run history. Further writes, reruns, cleanup, review, integration and publication require the task owner's next concrete instruction.
